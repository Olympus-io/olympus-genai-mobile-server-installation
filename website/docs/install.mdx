# Install Olympus

A quick check, then one Docker command. Pick your OS tab inside each code block; your choice is remembered across the page.

The installer command is the **same with or without a GPU**: the installer finds an NVIDIA GPU by itself. If you have one and want local AI models (Ollama, Stable Diffusion), step 2 makes sure Docker can use it.

---

## 1. Pre-flight check — 30 seconds

Run the snippet for your OS and look for three ✅ marks. Each ❌ tells you exactly what to fix before installing.

<Tabs groupId="os">
<TabItem value="linux-mac" label="🐧 Linux / 🍎 macOS" default>

```bash
docker info >/dev/null 2>&1 \
  && echo "✅ Docker is running" \
  || echo "❌ Docker is not running — start Docker / Docker Desktop and re-run this check"

df -BG / | awk 'NR==2 { gsub("G","",$4); if ($4+0 >= 30) print "✅ "$4" GB free on /"; else print "❌ Only "$4" GB free on / — need 30 GB+" }'

(lsof -i :8888 >/dev/null 2>&1 \
  && echo "❌ Port 8888 is in use — see Troubleshooting" \
  || echo "✅ Port 8888 is free")
```

</TabItem>
<TabItem value="windows-ps" label="🪟 Windows (PowerShell)">

:::tip Lines are intentionally long
Each check is one physical line so PowerShell pasted line-by-line still works. Use the copy button in the top-right of the block — don't hand-select.
:::

```powershell
if (docker info 2>$null) { Write-Host "✅ Docker is running" -ForegroundColor Green } else { Write-Host "❌ Docker is not running — start Docker Desktop and re-run this check" -ForegroundColor Red }

$free = [math]::Round((Get-PSDrive C).Free / 1GB); if ($free -ge 30) { Write-Host ("✅ {0} GB free on C:" -f $free) -ForegroundColor Green } else { Write-Host ("❌ Only {0} GB free on C: — need 30 GB+" -f $free) -ForegroundColor Red }

if (Get-NetTCPConnection -LocalPort 8888 -ErrorAction SilentlyContinue) { Write-Host "❌ Port 8888 is in use — see Troubleshooting" -ForegroundColor Red } else { Write-Host "✅ Port 8888 is free" -ForegroundColor Green }
```

</TabItem>
<TabItem value="windows-cmd" label="🪟 Windows (Command Prompt)">

The pre-flight check uses PowerShell — switch to the PowerShell tab for this step, then come back to Command Prompt for the installer if you prefer `cmd`.

</TabItem>
</Tabs>

### Got a ❌? Fix it here

- **Docker is not running** → start Docker Desktop, or `sudo systemctl start docker` on Linux, then re-run the check.
- **Not enough disk space** → see [System Requirements](./system-requirements) for what the install actually needs.
- **Port 8888 is in use** → **[how to clear port 8888](./troubleshooting)**. Most often this is **your own previous Olympus installer still running**, not another application. That page shows you how to tell which, then covers reopening the wizard you already have, restarting everything without reinstalling, or wiping for a clean fresh install.

## 2. Let Docker use your NVIDIA GPU (optional)

**No NVIDIA GPU?** Skip to [step 3](#3-run-the-installer). Olympus works fully without one, using cloud AI providers (OpenAI, Anthropic, Gemini) or an Ollama server on your network.

There is no special installer command for a GPU: the installer finds it by itself (it test-runs a container on it). Docker only has to be able to give the GPU to containers:

- 🟩 **NVIDIA Jetson (JetPack 6):** already done by JetPack, skip to step 3. The installer runs Ollama on the Jetson's GPU and suggests small models, since the GPU shares the board's memory with Olympus. Stable Diffusion is not available on ARM boards.
- 🐧 **Linux PC:** run the Linux one-liner. It installs the NVIDIA Container Toolkit if it is missing and checks that Docker can use the GPU.
- 🪟 **Windows:** Docker Desktop (WSL 2 engine) with a current NVIDIA driver already can. The PowerShell check confirms it.
- 🍎 **macOS:** Docker Desktop has no NVIDIA GPU support. Use cloud AI providers or an Ollama server on your network.

<Tabs groupId="os">
<TabItem value="linux-mac" label="🐧 Linux / 🍎 macOS" default>

```bash
if nvidia-smi >/dev/null 2>&1; then
  echo "✅ GPU detected: $(nvidia-smi --query-gpu=name --format=csv,noheader | head -1)"
  if docker info 2>/dev/null | grep -qi nvidia; then
    echo "✅ NVIDIA Container Toolkit already configured"
  else
    echo "⚙️ Installing NVIDIA Container Toolkit..."
    curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg && \
    curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list | \
      sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | \
      sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list && \
    sudo apt-get update && sudo apt-get install -y nvidia-container-toolkit && \
    sudo nvidia-ctk runtime configure --runtime=docker && \
    sudo systemctl restart docker && \
    echo "✅ Toolkit installed. Verifying..." && \
    docker run --rm --gpus all nvidia/cuda:12.2.0-base-ubuntu22.04 nvidia-smi && \
    echo "✅ Docker GPU access confirmed!"
  fi
else
  echo "ℹ️ No NVIDIA GPU detected — skipping GPU setup (this is fine)"
fi
```

</TabItem>
<TabItem value="windows-ps" label="🪟 Windows (PowerShell)">

```powershell
if (-not (Get-Command nvidia-smi -ErrorAction SilentlyContinue)) { Write-Host "ℹ️  No NVIDIA GPU detected — skipping (this is fine)" -ForegroundColor Cyan } else { docker run --rm --gpus all ubuntu:24.04 nvidia-smi -L; if ($LASTEXITCODE -eq 0) { Write-Host "✅ Docker GPU access confirmed!" -ForegroundColor Green } else { Write-Host "⚠️  GPU found but Docker can't use it. Update the NVIDIA driver and Docker Desktop, check Docker Desktop uses the WSL 2 engine (Settings → General), restart Docker Desktop and re-run this check." -ForegroundColor Yellow } }
```

</TabItem>
<TabItem value="windows-cmd" label="🪟 Windows (Command Prompt)">

The GPU check uses PowerShell — switch to the PowerShell tab for this step, then come back to Command Prompt for the installer if you prefer `cmd`.

</TabItem>

:::tip Do this before you run the installer
The wizard offers local AI models only when it finds a GPU that Docker can use. If the check fails, fix it, re-run the check, then go on to step 3.
:::

## 3. Run the installer

Pick your OS and run the command. It pulls the setup image (~few hundred MB) and starts the browser wizard at `http://localhost:8888`. An installer started the older way, with `--gpus all`, keeps working too.

<Tabs groupId="os">
<TabItem value="linux-mac" label="🐧 Linux / 🍎 macOS" default>

```bash
mkdir -p "$HOME/olympus/app" "$HOME/olympus/data" && \
docker rm -f olympus-setup >/dev/null 2>&1 || true && \
docker pull olympusmobile/olympus-master-setup:latest && \
docker run -d \
  --name olympus-setup \
  -p 8888:8888 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v "$HOME/olympus/app":"$HOME/olympus/app" \
  -v "$HOME/olympus/data":"$HOME/olympus/data" \
  -e HOST_PROJECT_ROOT="$HOME/olympus/app" \
  -e DOCKER_USERNAME="olympussupport" \
  -e DOCKER_TOKEN="dckr_pat_nnZK2QRyooOHm944bKzRTKo12-w" \
  olympusmobile/olympus-master-setup:latest >/dev/null && \
docker logs -f olympus-setup
```

## What you'll see while it runs

After running the command, the terminal will:

1. **Download the setup image** (a few hundred MB — fast).
2. **Start the setup container** in the background, then **stream its log output** to your terminal.
3. Eventually print a line that says the wizard is ready, something like:

   ```text
   ✅ Setup wizard ready at http://localhost:8888
   ```

When you see that line, **open `http://localhost:8888` in your browser** (or `http://<your-server-ip>:8888` if you're installing on a remote machine). Leave the terminal open — it'll keep showing logs you can refer to if something goes wrong.

:::tip Stuck on download?
First image pulls can be slow on metered or international connections — the setup image is small, but the full platform downloads later total ~6 GB across 30+ images.
:::

Once the wizard opens, head to **[Setup Wizard →](./wizard)** for the 9-step walkthrough.

## Air-gapped install (no internet on the server)

Olympus runs with no internet access at all, as long as every image is on the server before you start. **Use the Community edition:** an Enterprise licence must reach the licence server at least once every 7 days, or every user except the super-admin is locked out.

On a machine **with** internet access (same CPU architecture as the server):

1. Sign in to Docker Hub with the `DOCKER_USERNAME` and `DOCKER_TOKEN` from the install command above:

   ```bash
   docker login -u olympussupport
   ```

2. Pull the installer, then list the platform images it deploys:

   ```bash
   docker pull olympusmobile/olympus-master-setup:latest
   docker run --rm --entrypoint sh olympusmobile/olympus-master-setup:latest \
     -c "grep -h 'image:' /app/backend/bundle/compose/*.yml | sed 's/.*image: *//' | sort -u" > olympus-images.txt
   echo olympusmobile/olympus-master-setup:latest >> olympus-images.txt
   ```

   If you want the wizard's built-in test shares, add `olympusmobile/test-nfs-server:latest` and `olympusmobile/test-smb-server:latest` to the list.

3. Pull everything and save it to one archive (use `linux/arm64` for an ARM server):

   ```bash
   xargs -n1 docker pull --platform linux/amd64 < olympus-images.txt
   docker save --platform linux/amd64 -o olympus-images.tar $(cat olympus-images.txt)
   ```

On the **air-gapped** server:

1. Copy `olympus-images.tar` over and load it:

   ```bash
   docker load -i olympus-images.tar
   ```

2. Run the install command for your OS from above, **leaving out the `docker pull` line**.
3. In the wizard, pick:
   - **Private** with a self-signed or custom certificate;
   - the **Community** edition;
   - **Ollama on your network** for AI (cloud providers cannot be reached);
   - **production** file shares on your own NFS/SMB servers. For an SMB server that is not joined to Active Directory, choose `FULL_RW` or `READ_ONLY` access, not `AD_ACLS`.

The deploy tries the registry once, then uses the images you loaded; expect about two extra minutes. (Installers older than 14 November 2026 instead retried every image and then failed with *Failed to pull … images*.)

**Updating later:**
1. Build a new archive the same way, then `docker load` it on the server.
2. Run the install command again without the `docker pull` line. This starts the new installer.
3. Open **App-Updates** and run the update. It uses the loaded images when the registry cannot be reached.

**What needs the internet** and is unavailable offline:
- cloud AI providers;
- Let's Encrypt certificates;
- Telegram;
- voice-note transcription;
- reverse geocoding of photo locations (photos are still indexed);
- hosted MCP clients such as claude.ai. A desktop MCP client on your network works.
